# Dockerize-PostgreSQL-DB1 — Agent-1's database

A PostGIS 18 image holding **`agent_1_db`**, the part of the German states
data that [Agent-001](https://github.com/ishancoderr/Agent-001) owns. Agent-2's
database is the sister repository
[Dockerize-PostgreSQL-DB2](https://github.com/ishancoderr/Dockerize-PostgreSQL-DB2).
Each agent can reach only its own database; what it lacks it gets from the
other agent over KQML.

## What gets loaded

On the first start (empty data volume) the init scripts run in order:

| Script | |
|---|---|
| `10_postgis.sh` | from the `postgis/postgis` image: enables PostGIS |
| `init/20_agent1_data.sql` | Agent-1's data, generated by [germany-demographics-births-marriages](https://github.com/ishancoderr/germany-demographics-births-marriages) (`agent1_postgis_db.sql`, commit `257c186`) |
| `init/30_agent1_geometry_gaps.sql` | the geometry missingness of the thesis scenarios: Berlin's polygon and six city points (Munich, Aschaffenburg, Alzey, Babenhausen, Aßlar, Bad Ems) are NULL, so Agent-1 has to ask Agent-2 for them |

Tables:

| Table | Rows | |
|---|---|---|
| `states` | 16 | all federal states with their polygons (EPSG:4326) — Berlin's left empty |
| `state_demographics` | 330 | population, live births, marriages: 11 states, 1990–2019, with deliberate gaps (see `split_metadata.json` in the data repository) |
| `cities` | 1,782 | German cities as points (EPSG:4326) |

The result is identical, row for row, to the `agent_1_db` the agents were
developed and evaluated against.

## Use

**In the deployment** — `kqml-deploy` builds this repository as service `db1`,
reachable only by Agent-1, with the password from its `.env`. Nothing to do
here.

**On its own** (Docker Desktop):

```bash
copy .env.example .env        # set POSTGRES_PASSWORD
docker compose up -d
docker compose ps             # "healthy" once the data is loaded (about 15 s)
docker compose exec db psql -U postgres -d agent_1_db -c "\dt"
```

Connect with `localhost:5434`, database `agent_1_db`, user `postgres`.

Reload from scratch (deletes this container's data): `docker compose down -v`,
then `docker compose up -d`.

## Updating the data

Regenerate `agent1_postgis_db.sql` in the data repository, copy it over
`init/20_agent1_data.sql` (keep LF line endings), update the commit above, and
rebuild. The data only loads into an empty volume, so on a running system the
database volume has to be removed first.
